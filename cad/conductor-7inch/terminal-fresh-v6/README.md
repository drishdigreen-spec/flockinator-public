# FLOCKINATOR fresh terminal v06

A new model built from the supplied Retro Terminal Language brief, not a modification of the old shallow wedge. Visual/engineering study; **not a verified hardware-fit enclosure or sliced print job**.

## Design

ADM-3A / RobCo terminal language from the supplied brief: upright raked screen, shallow sloped lower deck, generous recessed bezel, blended screen/deck and screen/top junctions, beige monolithic housing and brown-black accents. Touch remains the main input; no added rows of knobs/buttons. MonoLisa Code and camera in the first O are retained from the owner's explicit requests. The local font file is not redistributed.

## CAD structure

One document, one Part Design Body per enclosure/inlay part. `Params` records primary dimensions, sources, derived side-profile coordinates and secondary sketch coordinate aliases. Fully constrained `SK_Master_Side` drives a symmetric Pad. Interior and apertures are native Pockets; insert bosses are native Pads; the screen has a Datum Plane. Large blends and rear corner fillets occur after the pockets and bosses. Text uses the brief's permitted inlay boolean exception. The base has a Pad, screw clearance Pocket and corner fillet. Visual-only glass/lens reference bodies are excluded from manufacturing exports.

Primary massing and all polygon sketches are expression-connected to Params; it is **not yet a completely dependency-linked production model**. Some camera/insert/base constraints, pocket lengths and generated font geometry remain explicit values in the generator. The font is regenerated by `build.py`, not live-parametric text recomputation. Do not claim every requirement of brief section 6 is complete.

## Proposed printing and hardware

Base: flat, bottom down, textured PEI, brown-black matte PLA. Housing: current export upright, beige matte PLA, interior supports needed beneath roof/other large internal overhangs. Bezel and text are aligned colour parts of the housing, not separate loose prints. Current upright orientation can cause repeated AMS changes; this first study does not satisfy the brief's preferred face-down, few-colour-layer print strategy. A deliberate split/reveal is still needed to optimise that. Review supports and all visible edges in the slicer; no support-free or print-time claim is made. Material substitutions for operating temperature require hardware/thermal validation. No G-code supplied.

Provisional closure BOM: four M3 inserts matching the brief's nominal M3 x 5.7 x 4.6 mm item and four underside M3 screws; confirm insert manufacturer, pilot bore, screw/head dimensions and length with a coupon. Base has 3.4 mm clearance holes. No inserts, screws or adhesive feet are included in files.

## Outstanding requirements / deliberate stage limitations

- Physical v1.6 board mount coordinates, complete touch-glass/module envelope, screen clamp, cable reach and actual port alignment remain unmeasured. Rear bay is generic. Do not install powered hardware unsecured.
- Speaker location/cradle and sealed back volume are not yet added to this fresh model. Horizontal grille is a proposed vent/speaker area, not an acoustically validated speaker mount.
- Camera hole and dark lens reference do not establish camera retention, optical direction or clearance; the lens diameter is assumed.
- Interior profile has local thickened transition zones to support large outer blends; these exceed nominal wall thickness locally. Interior shell offset is not a uniform 3 mm everywhere.
- Aperture recesses presently have crisp square panel corners; aperture chamfers, independent R3-R6 bezel corners, remaining outer edge rounds, grille-slot edge chamfers and front-wall moulding draft are not complete.
- Insert-boss ribs, base alignment pins/lip, reveal groove and foot recesses remain to be designed. Base currently seats against an open underside rim. Fastener heads are underneath but not recessed under feet yet.
- No new optional sensors or knobs added; only the owner's earlier camera-O provision is retained.
- `validation.json` proves model/mesh geometry only. Hardware fit, dimensional changes after regenerating, thermal behaviour, slicing and physical printing are not verified.

## Typography/camera correction

Verified installed `$HOME family MonoLisaCode, subfamily Regular, PostScript MonoLisaCode-Regular; SHA-256 `63e17c766fd576873c46ead7473ea41fac9f41932916b55d87ea22bf5dcf0bc2`. Font metrics: 1000 units/em, cap height 700, character advance 640 for all letters in FLOCKINATOR. `font-specimen.png` renders the installed font directly for comparison.

Previous code used real font outlines but centred each glyph independently and advanced by its visible width; that destroyed monospaced spacing. Current text uses a common baseline and fixed advance (10 mm cap height, 9.142857 mm character advance), preserving each glyph's natural side bearing. Camera gets a 14 mm replacement cell. The first O is now **omitted**, and the lens/aperture occupies that cell; there is no printed O ring. The second O remains a normal font glyph. Aperture still assumes 10 mm lens plus 0.6 mm diameter clearance. Ten text solids are intentional.

Native, STEP, 3MF and STL exports were regenerated and passed geometry/mesh checks after the correction. Hardware-fit and printing caveats above remain.

Final font conversion fix: FreeCAD's native ShapeString contour handling also altered some glyph outlines. The corrected model uses outlines extracted directly by Qt QRawFont from the verified TTF file, cleaned as planar polygons with at most 0.003 mm simplification (0.001 mm topology cleanup), retaining a common baseline and fixed advance. It does not rely on reconstructing native ShapeString wires. `font-contours-clean.json` is the local generated lettering-outline dependency used by the builder. Geometry and mesh checks passed after this final correction. Camera remains a replacement for the first O with no surrounding printed glyph.

Front-lip correction: outer housing corner selection now includes both short front lip vertical edges as well as the tall rear edges. Housing front corners now have the same R6 plan radius as the base. Rebuilt native/STEP/3MF/STL exports passed BRep, mesh-solid and six pairwise overlap checks. Remaining hardware-fit caveats are unchanged.
